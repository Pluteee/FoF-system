# 分层协同系统、填报与 AI 尽调演示说明

## 底层企业轮次与估值分布

`bottom-profile.js` / `bottom-profile.css` 在国家驾驶舱的子基金/直投区域分布后追加两张三地区域对比图。默认仅统计子基金穿透企业，可切换穿透+直投申请标的。区域内按去除“（第二轮）”后的企业名称去重；三地总体再去重，因此区域合计不等于三地去重数，企业主数据仍需进一步确权。当前默认21家，含直投申请时58家。

融资画像来自 `demoScenario.enterpriseProfiles` 的独立演示快照（截至2026-10-16），显式列示最新已知轮次与人民币投后估值；不是深圳演示样本字段，也不按项目编号或融资金额推算。轮次分种子/天使、Pre-A、A、B、C及以后、战略/其他、未披露；估值分[0,1)、[1,5)、[5,10)、[10,30)、[30,+∞)亿元及未披露。未披露纳入图中分母并单独显示，不作为0。

企业有已确认项目报送时，仅纳入金额有效、具有有效估值日期、依据明确注明投后口径的估值，万元换算为亿元，按估值日、报告期和版本选最近有效值。使用确认快照字段而非后续可编辑稿；只有草稿/待审值不能覆盖，真实报送缺失或口径不明时不以演示估值掩盖。轮次仍单独注明演示来源，不从自由文本融资描述强行提取。

色块、区域可下钻查看企业、覆盖区域、轮次及日期来源、估值与口径、确认报告编号；支持分页、清除筛选、企业档案跳转及当前筛选CSV导出。驾驶舱HTML图表报告包含两图及当前范围的全部企业明细。核验：`node demo/bottom-profile.test.js`，覆盖重复企业、缺失、区间边界、有效日期、确认快照、万元换算和草稿隔离。

## 国家驾驶舱树图与区域比较（2026-10-21）

`dashboard-visuals.js` / `dashboard-visuals.css` 提供国家驾驶舱的四层投资树及区域比较。国家 → 三地区域 → 所选子基金 / 直投记录 → 已有底层企业路径；用户切换区域及对象查看完整名录，底层企业按名称归并、每组三家，可分页。节点可进入原有区域、基金、直投和企业档案。直投记录本身对应企业，不虚构额外子基金层级或投资路径。不存在的底层关系明确显示待补充。图支持放大/退出和Escape，连线随容器尺寸重绘，尊重减少动态效果设置。

国家资金与演示路径仍标注口径；演示样本申请不等于已交割或实缴。页面标题调整为「国家创投母基金投资管理驾驶舱」，移除顶部迷你演示样本/演示图例及确认报送快照条；不删除已确认报送数据或其重算机制。国家风险模块标题为「风险分析」，联合核查功能保留，区域在事项与协同承接。

上海演示子基金拟注册地为上海、苏州、无锡、杭州；北京区域为北京、天津、石家庄、廊坊。只调整演示注册地，不改变基金归属、数量、金额及深圳演示样本。所有城市图、筛选和导出共用同一字段。

区域比较以三地识别图标、资金进度、基金/直投数量、平均申请额、主要产业及城市分布呈现。数量最多、直投申请额最高、基金单支均额最高根据当前台账计算并处理并列；空样本不参与均额排名，全零不输出赢家。实缴进度按实缴/认缴计算，不按三地区域最大实缴额归一化。数量为虚构样本与演示情景的展示比较，不代表经营业绩排名。

## 区域版募投管退导航

`workflow-lifecycle.js` / `workflow-lifecycle.css` 在模拟账号入口加载，仅重组区域母基金版，国家、子基金和企业的功能范围保持原样。区域版移除顶部角色横条及独立「任务工作台」，保留驾驶舱，业务按以下阶段组织：募（募资与出资结构、资金计划）、投（储备与接洽、子基金管理、直投管理、AI研究与模拟投委会）、管（穿透、管理人评价、事项协同、定期报送审核）、退（退出计划与回收）。桌面为分组侧栏，窄屏为总览/募/投/管/退阶段与页内二级导航，不依赖长横向滚动菜单。

原 `home` 路径在区域版映射到定期报送；带选中报告的旧任务链接继续进入相应报告，不删除任务、材料、审核权限或历史。国家联合核查任务迁入「事项与协同」。募资页区分目标规模、演示国家认缴/实缴和缺失的其他LP台账，不以差额推算实际募集或逾期。

退出计划按区域保存于 `diki-public-regional-exit-plans-v1`，支持经办人员登记对象、方式、预估回收、责任人、预计日、持有依据与计划假设，并记录推进历史；领导账号只读此计划。计划状态不构成退出审批或真实回款。确认退出明细采用已确认报送的最新版本，同主体同年度年报优先于季度；演示退出案例单独展示，不与确认回款及预估回收相加。原Excel是立项/申请资料，不能据此认定已投可退出权益。

## 国家版证据化尽调工作台

国家侧菜单「AI 尽调」由 `diligence.js` / `diligence.css` 接管原入口，不增加一级菜单。基金、管理人、项目分别有8、8、9个核查章节及16、16、18类材料；保留4章团队核验。模板是业务设计，不把管理人登记材料要求等同于所有场景的法定尽调要求；页面提供协会材料清单与内控指引参考链接。

任务流为范围与资料截止日 → 材料提交及人工摘录 → 逐章核查 → 问题补正 → 报告生成 → 人工复核。任务、证据索引、问答、问题、日志及冻结报告保存于 `diki-public-diligence-workspace-v2`。旧 `diki-public-demo-dd-cases-v1` 清单及复核意见只读保留。与正式档案、审批、出资状态隔离，不会自动通过投资决策。

附件（每个不超过20MB）保存于本机 IndexedDB `diki-public-diligence-evidence-v1`，保留多次补交文件、时间和可用时的SHA-256摘要，可下载。上传不解析内容，也不代表核验；PDF/Word/Excel须人工登记证据位置、摘录和核验说明。标记已核验需证据摘录、位置、核验人和说明；不适用需核验人和理由。“已核实”章节只能引用已核验材料。材料补交或修改后，引用它的已核实章节重置待核查，旧版报告不变。

问答支持预设及自定义问题，根据主题匹配章节、档案快照和当前核查状态，明确输出规则式研究提纲，不声称模型分析或外部核查。未接入大模型、OCR、PDF/Word/Excel自动解析及外部工商/诉讼数据库。材料中内容按数据转义展示，不执行指令，不自动发送到外部服务。

每版报告冻结执行摘要、来源事实、逐章判断与证据、风险缺口、问题责任人和期限、后续条件、材料附件索引及研究记录。支持复制全文、文本导出、HTML报告导出及浏览器打印PDF；附件不随报告自动打包。底稿更新后旧报告标为需生成新版；材料未核验、章节未完成/待补正、问题未闭环或报告已过期时不能标记人工复核完成。已复核意见不可覆盖，后续需新版。复核身份为本机文本模拟，不是真实签名或服务端权限。

验证：`node demo/diligence.test.js`；完整浏览器流程还需验证本机附件留存、补正闭环、报告版本隔离、复核门槛及桌面/窄屏显示。

## 公开虚构数据口径（2026-10-26）

`source-data.js` 是 `generate-synthetic-data.cjs` 独立生成的虚构样本，不再导入或逐字段对应任何私有工作簿。深圳、上海、北京仅用作演示地域，区域基金及管理机构均使用虚构身份。

深圳样本含34支子基金、38笔直投记录、37家去重直投企业，保留技术ID及重复轮次测试结构。名称、注册城市、行业、业务摘要及金额全部重新生成；合计由样本计算，既不是实际经营规模，也不是原始资料的变换披露。无真实机构对照表、照片标识、原始行号或附件链接。

页面统一标识“公开演示 · 全部业务数据均为虚构”。确认报送、尽调附件、风险记录、研究历史等改用 `diki-public-*` 存储空间，旧版本机内容保持原样且不被公开演示读取。

运行 `python3 demo/source-workbook.test.py` 校验虚构样本标记、唯一ID、合计和重复轮次；无需私有工作簿或openpyxl。运行 `node scripts/check-public-data.cjs` 检查公开数据与路径，再用 `python3 scripts/package_public_demo.py` 生成允许列表发布目录及ZIP。原始资料、OCR、预览、私有交接与本机依赖不进入发布包。

## 本地演示怎么走

打开 `index.html`，从侧栏「切换系统身份」进入独立的模拟登录界面（`index.html?workspace=workflow`），而不是在「协同填报」栏目里切换角色。这里有国家母基金版、区域母基金版、子基金 / 直投项目版的不同工作台。建议演示顺序：区域审核员发布子基金季报任务 → 子基金填报人员填写并提交 → 子基金负责领导内部复核并批准报出 → 区域审核员确认或退回。确认后再查看区域工作台的确认统计与流转记录。区域报国家、直投项目报区域也按同样的两级审核逻辑演示。登录页可重置**仅由分层协同演示创建**的记录。

原有「协同填报」仍保留为早期流程原型；区域/子基金/项目独立工作台（同一演示页面的 `?workspace=partner` 入口）也已补上本机构负责人审核。新演示入口是三类系统界面与跨机构待办的主要展示路径。已确认数据反映到相关档案、画像和穿透视图；待审稿不参与重算。进入「AI 尽调」可以生成四类规则式核验清单。

模拟登录与工作台链接参数仅用于选择演示身份、对象和报告期，不是授权凭据。正式系统应由服务端生成带有效期、可撤销的邀请，接收人登录后校验机构成员关系，再打开有权访问的区域、子基金或项目工作台。三个工作台应通过同一套共享数据库和审核服务协作，而不是依赖浏览器跳转“回传”数据。旧版 `reporting-entry.html` 链接也已转向独立工作台。

身份切换不是登录或真实授权，浏览器本地存储不是共享数据库。新工作台支持本机 IndexedDB 附件和材料索引，早期填报原型仍只记录名称 / 编号。不得将本演示用于正式报送、尽调结论或个人评价。

## 企业工作台与定期报送

### 模拟投委会与导航收敛

区域和子基金的「AI研究工作台」新增「专题研究 / 模拟投委会」页内切换。模拟投委会支持从本机构储备、区域项目或本基金已投组合带入对象，亦可手动填写。系统预设产业、成长、财务、合规四类委员；自定义方案可编辑名称、讨论风格、关注偏好、产业阶段偏好、金额上限、现金支撑关注线和红线，并按机构保存于 `diki-public-simulation-committee-config-v1`。系统预设紧凑展示，自定义按委员展开编辑。

模拟运行仅使用填写的事实、核查状态和明确规则；文字红线未核实时形成补证意见，标注已触及/未触及时必须给出核查依据。结果包含委员意见、规则依据、分歧、后续问题和事实/配置快照，保存于 `diki-public-simulation-committee-history-v1`，支持历史恢复、复制及导出。不会自动改变储备阶段、正式投决或投资状态，未接入真实模型。

区域和子基金移除独立「报送记录」菜单。所有历史版本及审核轨迹保留在「定期报送与审核」，通过全部报送记录、待填报/补正、待我审核、确认归档四个视图筛选。

区域移除独立「风险联动」菜单，国家主驾驶舱和国家模拟账号驾驶舱展示 `national-risk.js` 提供的跨区域关联图、企业/管理人影响范围与联合核查任务。关系交叉不自动判为风险，直投拟出资与间接归属测算分别展示。国家创建任务时填写事实、来源和截止日，任务保存于 `diki-public-national-risk-tasks-v1`；区域审核员在「管 → 事项与协同」反馈本区域事实，收齐区域反馈后由国家关闭任务。此为浏览器本地协同演示，非真实跨机构消息。

企业账号从模拟登录进入后默认打开 AI研究，一级菜单仅保留 AI研究、事项与协同、定期报送。研究提供行业、竞品、融资准备、客户与供应链的规则式底稿，支持自由提问、复制、导出、历史恢复，并可将研究结果带入协同事项草稿。企业事项由所属区域在「资源协同」接收、回复办理结果，企业确认后关闭；记录保存在 `diki-public-enterprise-affairs-v1`。

`workflow-reporting.js` / `workflow-reporting.css` 共用原报送记录与审批路由。区域、子基金通过「定期报送与审核」，企业通过「定期报送」进入。支持2026年四个季度与年报，可发布任务或由本机构填报人员自主发起。章节根据主体与季/年报展开：企业经营及融资变化、子基金募资/财务/逐笔投资退出、区域计划执行与协同，以及共同的重大事项、下一期计划和材料。年报另需审计机构或未审计原因、年度复盘及季度差异说明。

新报告的 `details.fields` 保存结构化字段，`details.investments`、`details.exits` 保存一对多交易，`details.evidence` 保存材料索引，`details.normalizations` 保存原始与格式标准化值。`values` 保留兼容摘要，`issues` 保存字段级问题与补正回复，`confirmedSnapshot` 在上级确认时冻结。报告支持按章节保存和切换、上期确认值对照、核验定位、退回重审、HTML导出、确认后新建更正版本。草稿、内部批准及待上级审核均不参与确认统计。

规则覆盖必填、统一字典、非负/允许负值、实缴不超过认缴、本期不超过累计、现金勾稽、投资退出日期及重复交易、估值日期和依据、材料缺失、上期重大变化和年报覆盖说明。清洗仅做可解释的格式标准化，不推断缺失数值或自动确认业务事实。

年报可从各季度最新确认版归集参考：四季齐备且相关字段完整时才累加全年流量；期初取一季度期初，期末取四季度期末。季度缺失时不自动形成全年流量。来源报告编号和版本保存于 `annualSources`。`workbench.js` 重建穿透关系时使用每期最新确认版，年报替代同年季度交易，避免季度、年报和更正重复计入。缺失企业产业/地域标注待补充，不以基金产业/地域冒充企业属性。

附件原文件保存在本机 `diki-public-report-evidence` IndexedDB；报送记录只存文件引用。可上传或仅登记材料索引，界面明确区分二者。HTML导出包含数据和目录，不打包附件。清理浏览器数据会同时影响本地记录及附件。

## 已有系统 API 接入演示

区域和子基金的报送中心提供「从已有管理系统导入」，由 `workflow-integration.js` 承载。流程为来源系统配置 → API响应JSON样例/JSON文件 → 字段映射 → 统一模板预检 → 导入本机构草稿 → 人工补充 → 内部复核 → 上级审核确认。

本机仅保存来源名称、HTTPS地址与认证方式于 `diki-public-system-connectors-v1`，不收集密钥、不向地址发送真实请求。数据格式包含 `batchId`、`period`、`report` 字段对象及 `investments` / `exits` 数组。仅本机构填报人员可导入，检查批次重复、字段映射冲突和正在审核的报告；只填充已有草稿空白项，冲突阻断且不覆盖。导入批次保存在报告 `importBatches`，包括来源系统、原始映射值、操作者和时间，可在报告中回溯。真实对接仍需服务端凭证托管、认证授权、调度和接口适配。

## 角色与记录归属

### 储备接洽与驾驶舱

从 `workspace=workflow` 的账号卡片进入区域或子基金工作台，驾驶舱展示机会阶段、产业、来源渠道、责任人、投资组合分布、按月投资节奏、资金回收及集中度。储备统计取当前机构记录；组合取演示投资路径；确认实缴只取已确认报送。没有历史阶段迁移样本时，仅显示阶段分布，不将它命名为转化率；无投资日期的路径不参与趋势统计。

区域菜单「储备与接洽」、子基金菜单「项目储备与投决」承载正式投资前的工作。记录存于 `diki-public-workflow-prospects-v1`，按 `region:<id>` / `fund:<id>` 归属，包含类型、产业、地域、来源、联系人、责任人、意向金额、下次跟进日及过程日志。支持新建、筛选、交流跟进、阶段更新、暂缓和终止。阶段通过不自动写入正式台账或确认报送；管理人接洽没有拟投资额。这里的范围隔离仅为本地演示逻辑，不构成服务端授权。

新模块为 `workflow-operations.js` / `workflow-operations.css`，由工作台启动脚本加载。示例储备明确标注演示，AI准备访谈时读取对应记录；AI仍为规则式演示。登录页的「重置演示记录」仅清除原报送流程数据，不清除本模块储备记录。

| 角色 | 可维护对象 | 上级审核 | 可查看的报送 |
| --- | --- | --- | --- |
| 国家基金总系统 | 发布区域任务；审核区域正式报送 | 本级审核区域报告 | 区域报告及汇总视图 |
| 区域母基金工作台 | 本区域季报；发布下级任务；审核子基金与项目 | 本机构负责领导内部复核后报国家 | 本区域季报及所属子基金、项目报送 |
| 子基金工作台 | 本基金季报及底层投资 | 本机构负责领导内部复核后报区域 | 本基金报送 |
| 项目工作台 | 本项目经营、融资、资质与风险动态 | 本机构负责领导内部复核后报区域 | 本项目报送 |

每个填报机构的状态应明确区分：`待填写 / 草稿 → 待本机构审核 → 待上级审核 → 已确认`。内部或外部退回都回到填报人员；再次提交时重新经过本机构负责人。仅最终确认版进入统计。

正式接入时，权限须按 `organization_id`、`object_id` 和人员任职关系在服务端校验，不可信任浏览器传来的角色或对象 ID。区域对下级的邀请应绑定投资或管理关系、有效期、报送模板和撤销机制。当前项目工作台以区域直接投资项目为例；子基金所投底层企业可在后续阶段增加“子基金初审 → 区域抽核”的审核链。

## 基金管理人线索与合作档案

管理人库不应只从子基金名单反推。机构主表可以先录入尚未立项的线索，记录机构名称、统一标识、来源、对接区域、投资方向、当前阶段、最近接触日期、下一步动作与日期；阶段可为潜在对接、接触中、尽调中、暂缓跟进。团队履历、历史业绩、风险与合作记录逐步补充，并分别标注“待提供、待核验、已核验”。已有基金关联的机构单独标为“已立项入库”，但基金目标规模不能冒充实际 AUM。未立项线索不得进入管理关系数、子基金规模或投资穿透统计。

正式系统宜使用机构唯一 ID 合并同名线索与已合作档案，保留接触历史和来源，不因关联第一支基金而丢失前期记录；权限上允许区域基金维护本区域跟进记录，国家基金查看跨区域去重机构画像。

## 填报字段

| 表单 | 字段 | 必填与校验 | 主要去向 |
| --- | --- | --- | --- |
| 区域季报 | 数据截至日期、年度出资计划、年度投资计划、本期新增子基金数、本期新增直投数、重大风险与待办、经营摘要、依据材料名称 / 编号 | 均必填；金额和数量非负 | 区域档案及驾驶舱已确认摘要 |
| 子基金季报 | 数据截至日期、已认缴、已实缴、风险状态、运营与投资摘要、依据材料名称 / 编号 | 均必填；`0 ≤ 实缴 ≤ 认缴` | 基金档案、画像及资金穿透 |

正式系统建议将子基金报告中的「新增底层投资」拆成一对多明细表，一笔记录对应一个企业、投资主体、轮次、日期、投资额及证据。当前单企业字段只是为了在静态 demo 中演示确认后生成一条穿透关系。企业名称去重应辅以统一社会信用代码和人工合并，不宜只凭名称。

## 发布口径与回溯

一份记录按「待填写 → 草稿 → 待本机构负责领导审核 → 待上级机构审核 → 已确认」流转。内部或外部退回都由填报人员补正，补正后再次经过本机构审核。已确认版本冻结；更正需新建 `v+1` 并再次审核。保存每次操作的人员、时间、理由、字段前后值、材料哈希及当时适用口径。看板查询只读取确认快照，并显示来源、报告期和最近确认时间。对跨区域同一管理人或企业的统计，分别保留投资关系数和去重主体数，避免混算。

本 demo 在浏览器 `localStorage` 中模拟上述流程；关闭或清理浏览器数据可能丢失记录，多个用户之间不共享，也没有服务器端防篡改能力。AI 页目前是可解释的规则清单，不调用模型、不读取外部资料、不自动给出投资决策或人才评级。
